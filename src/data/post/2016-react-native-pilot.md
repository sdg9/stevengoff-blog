In January or February 2016, I pitched rewriting Discover's native mobile application in React Native.

The starting point was the [Halloween party and party-game experiment](/2015-halloween-react) from the previous fall. Learning React, Redis, Redux, and React Native for my own curiosity had given me a different way to think about the mobile work in front of us.

## From an idea to something we could try

The surviving Bitbucket repositories line up with that timing. DRN contains January 25 setup files, February React Native work, and a February 18 merge of an iOS proof of concept. Its documentation explains React Native and Redux alongside conventions for organizing and testing the application.

Those documents matter to the story: adopting a framework is also about making its approach understandable to the next person who has to work in it.

That summer, the pilot was **me and one intern**. The DRNPOC repository preserves two Android build commits from July 29, 2016: “initial build” and “new POC.” The follow-on DRNv2 history shows continued development through August, including reusable scaffolding and navigation work.

The code and build dates corroborate the development period. The team size and the decisions around the pilot come from my memory of doing it.

## A pilot became a team

By December 2016, we had started with a team. In January 2017, we got fully rolling with offshore colleagues as well.

What began as a small experiment had become an organizational effort. My recollection is that the resulting move to React Native eventually saved Discover **upwards of $10 million per year**. That is a remembered business outcome, not a number a Git repository can independently substantiate.

The [Payday mobile app](/2016-payday-mobile) belongs in this period too: another place I was putting React Native to use. But the origin of the learning thread was the party and the interview process, rather than discovering the framework through Payday.

## Curiosity can have a long tail

There was no way to predict that path while playing Jackbox. A Halloween party led to a homemade game. The game led to learning tools. Those tools led to a pitch, a pilot, and a much larger team effort.

That is one of my favorite examples of why I keep making side projects. Sometimes the most consequential thing a project produces is what you learn well enough to use somewhere else.
